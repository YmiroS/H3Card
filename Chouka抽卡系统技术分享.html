CHOUKA / SYSTEM BOUNDARY01 / 12
CHOUKA 管什么，COMFYUI 管什么

业务编排与节点执行明确分层

Chouka Web业务参数 · 素材 · 项目操作
HTTP API
Chouka Server项目、权限、Graph、任务、资源、调度
API Graph
ComfyUI模型、节点、GPU 执行、history、output
Chouka 负责业务治理
  • 浏览器画布、业务参数和项目协作
  • 用户、项目 ACL 与素材访问权限
  • Manifest 参数注入和任务调度
  • 产物归档、费用、产能和管理页面
ComfyUI 负责推理执行
  • 校验 API Graph
  • 加载模型与自定义节点
  • 执行节点图并发送进度事件
  • 写入 history 与 output
核心结论：Chouka 是 ComfyUI 之外的业务编排和治理层，不是新的推理引擎。
System Context任务状态与授权产物通过 Chouka 返回浏览器

CHOUKA / SCHEDULER09 / 12
Worker 调度条件

先过滤资格，再按缓存亲和性排序

1. 在线可用enabled + heartbeat 未过期
2. 当前空闲idle 且不在同步模型
3. 节点齐全包含全部 required_nodes
4. GPU 合格型号、显存、特殊策略
5. 亲和排序同能力 / 同模型族优先
6. 分配租约生成 lease_token
Worker 心跳来源运行事实
/system_statsGPU、显存、系统
/object_info节点 class_type 集合
/queue本机队列占用

同时上报当前任务、租约、同步状态和模型缓存信息。

调度边界需要版本治理

节点类匹配只能证明节点“存在”，不能证明插件版本、模型文件、ComfyUI 核心补丁完全一致。

因此仍需维护 Worker 执行环境版本和发布清单。
